# nats_rw 开发防再犯清单（Bug 复盘 2026-10）

> 依据：阶段一至三 + 代码审查轮的全部实际缺陷（28 项），全部有提交/日志/测试证据。
> 用法：每个新阶段开工前、每次提交前过一遍本清单；新增教训按类别追加。

## 根因分类与案例

### 一、凭记忆猜 API（最高频，约占一半返工）

| 案例 | 代价 |
|------|------|
| async-nats：`StreamMessage` 路径、`State.last_seq→last_sequence`、HeaderMap 迭代形状 | 3 轮编译 |
| `Value::BLOB(string)` 是字面量语义（非 ASCII 裸字节被拒） | 跨阶段潜伏，中文测试才暴露 |
| COPY 选项语法连猜错两次（`:=`→`=`→空格分隔）；选项存放字段读错（parsed_options 实为 info.options） | 3 轮 |
| `Identifier` 无 ToString、find 需构造、模板消歧 | 1 轮 |

**规则 L1**：不熟悉的 API 面一律先证后写——读官方源码头文件 / docs.rs / 本地参考实现（正例：照 nats_js 源码写的注册代码一次通过；反例：所有上表条目）。
**规则 L2**：同类 API 家族（Value 构造器、Literal 体系）第一次用时，把候选 API 全部查一遍再选，不用"最像的那个"。

### 二、测试盲区与假阴性

| 案例 | 代价 |
|------|------|
| ASCII-only 载荷掩盖 `Value::BLOB` 字面量语义整整一个阶段 | 阶段三中文测试才爆 |
| run-all.sh 从未整体执行（审查已预警），cd 错层 | 数小时后首次整跑必败 |
| 非平面向量路径（字典/常量）从未被行使 | 审查静态发现 F1 |
| 播种失败被 `>/dev/null` 与 `;` 链吞掉，测试状态污染误报"双发" | 一轮误诊 |

**规则 L3**：round-trip 测试数据必须含 **非 ASCII（中文）、二进制（\x00/\xFF）、空串、NULL** 四类——本项目单条中文测试抓住了两个真 bug。
**规则 L4**：每个交付脚本（run-all 等）在"完成"声明前必须**以最终形态整体执行一次**；分步通过不等于整体可用。
**规则 L5**：排障时先怀疑状态污染（上一轮残留），再做代码归因；诊断前先重建确定性基线（重新播种/清流）。
**规则 L6**：排障命令禁止吞错：显式 rc、不用 `>/dev/null` 跑关键前置、批处理 `set -e` + 逐项校验。

### 三、环境与基础设施假设未验证

| 案例 |
|------|
| nats:2.11 是 distroless（无 shell）→ 容器内 healthcheck 不可能 |
| Docker Hub 不可达 + daocloud 对 synadia 命名空间 403 |
| 双全量构建目录打满 935G 磁盘 |
| ssh 会话拆除杀死 docker CLI 子进程（"builder not running" 幻觉） |
| github.com:443 间歇失联（api.github.com 却通）→ 改用 API tarball |

**规则 L7**：对"应该可用"的基础设施先做**最小验证**（镜像能拉吗、容器里有 shell 吗、端口通吗），再写进 compose/脚本。
**规则 L8**：共享主机资源（磁盘/镜像）建立配额习惯：同一时间一个构建目录、镜像逐个拉取校验、大文件日志限界（run-all 五要素已固化）。
**规则 L9**：网络受限环境的标准替代路径：docker 用镜像前缀+retag，源码用 api.github.com tarball，git 子模块改 vendor。

### 四、语义想当然

| 案例 |
|------|
| `create_or_update_stream` 会静默改写既有流过滤器（F2） |
| COPY 的原子性直觉 vs JetStream at-least-once（F4） |
| `batch_size` 实为并发度；时间过滤与 seq 是 AND 而非"二选一" |

**规则 L10**：凡有副作用的 API（update/create_or_create/overwrite 家族），先读语义再选；"名字里带什么"不算证据。
**规则 L11**：语义含混处（哨兵值、静默截断、过滤器组合）要么写测试锚定，要么在设计债表登记——不许默认。

### 五、Shell/转义/工具链陷阱

| 案例 |
|------|
| sed 误伤（scan 的 `:=` 被批量替换）；python 替换转义层级两次失败 |
| `$?` 被外层 shell 提前展开；pkill 自匹配杀会话 |
| 嵌套引号 ssh 命令 EOF；CRLF |

**规则 L12**：改文件一律用编辑工具（Edit/Write）或专用脚本，禁用 ad-hoc sed 批量替换跨语义区；必须批量时先 `grep` 预览命中范围。
**规则 L13**：ssh 长命令一律 heredoc（`bash -s <<'EOF'`）；`$?`/变量在远端展开的要转义；pkill 模式避开自身命令行。

### 六、根因误诊

| 案例 |
|------|
| ASan 退出风暴先归咎自己的 runtime 析构（Box::leak 是错误方向的修复），实为宿主 ASLR×旧 libasan 环境问题 |
| "count=2 双发"先怀疑 sink 双调，实为播种失败的状态残留 |

**规则 L14**：根因结论前先做**可复现实验**（并行轮的 0/10 风暴复现是典范）；"合理叙事"不是证据。
**规则 L15**：修复后若现象未消失，立即推翻假设重来，不在原方向加固。

- API 预检流程（docs.rs/头文件先读）——本清单将其从习惯升格为规则 L1/L2
